When loading the app it will have an elegant design. The main screen will contain:

a sidebar that contains a list of all section types such as 'featured-lifestyles, featured-areas, welcome, hero' and others that will become more clear with the html files i provided for two different templates with the new standard i created. The sidebar takes up like 20% of the screen. The user would decide which of the options from the sidebar to use and drag that option to the large area beside the sidebar that fills the rest of the screen. once an option is added by a user, it disappears from the option list in the sidebar. but appears again if the user decides to remove that option from the main template builder area. Speaking of main template builder area, this is where the options are dragged to. Once dragged in, a modal will open that forces the user to select a template to pull this section from. Some templates don't have a 'stats' section for example, so those templates would not be displayed as an option. After the user selects which template to pull from, the main content section is updated to display the section type you chose and the template you are pulling from. additionally there is a trash button to remove it and put it back in the sidebar, and up and down arrows so the user can change the position of the section in the list. for example, if they added a hero, stats, and welcome section in that order but realized it should have been hero, welcome, stats, they should just hit the up arrow on the welcome section to move up its place in the list.

That is how it functions when building a template. there is also a button in the main content section to live preview what you have built with at toggle for mobile view.

there is a button to output this template as html, css and js.

The top navigation is simple: the name of the app on the left, and a button at the top right that says 'Manage Templates' that, when hovered, displays two sub items that are 'Add New Template' and 'Edit Template'.

If choosing add new template, it will open a modal and it will have a similar layout like the home screen with the sidebar options and an area to drag in the options. after you drag an option in, it will display the trash, up and down arrows but doesn't require the user to select a template. After the user has selected the section types they want to use, they click the next button, this opens a new modal that will display every section they selected in order, and each section has the following items: html input, css input, js input. lastly there is a 'global js' and 'global css' input that effects either the whole design or the host cms the designs will be used on.

the user would then need to fill in the html, css and js for each section. once that is completed and they provide a name for the template, they can save the template into the database. must not add to database if template with same name exists.

Additionally, when the user clicks the 'add new template' button and the modal opens, there is another button that says 'upload template'. if the user selects this button instead of dragging options from the sidebar, a new modal will open that will ask for the html file, css file, and js file.

It will automatically intelligently isolate each section in the html file. if for example, there is a div that is at the same level as the other sections in the html, it will include that div as a possible section alongside the others in the same way it would if creating a new template manually. the system would also isolate the css. for example, if the user uploaded the files and it found these sections: .hero, .welcome, .stats, .featured-areas, .featured-lifestyles, it would then find all of the css rules that include those class names in the css for that section. it would copy the entire selector and rule exactly the same as from the original css file. any other css that was not included alongside the sections will be added as 'Global css' The js the user provides will be recognized as 'Global js'. 

after the user accepts the html, css and js for every section, accepts global css and js, and then names the template, it will be saved into the database.

If the user clicks the 'edit template' button, it will bring up a modal that displays a filterable list of all templates in the database. After selecting a template to edit, it will bring up a modal identical to manually creating a new template where it displays all of the sections with the html, css and js, and then the global css and js and template name. user should be able to modify or delete any of the content. this includes deleting sections, modifying html, css or js in sections, changing section order, changing template name, or deleting the whole template. all of those settings should be available when creating a template as well or uploading a new template, they all should use a similar modal.

Also, when on the main page and creating a template from sections, after the user drags an options and it requires the user to select a template to pull from, make it also a filterable list. the filterable lists should allow filtering by section type and also by name.
